# Repo Pulse — пульс собственных плагинов

Отслеживает входящие issue, PR, комментарии, ревью, ошибки CI и заявки владельца в маркетплейс. Показывает пункты по репозиториям и создаёт связанный тред агента. Интерфейс: English по умолчанию; русский при `document.documentElement.lang=ru*`, маркере языка Pokecut или активном русификаторе BB, оставляющем html lang английским. Заголовок, счётчик, статусы, кнопки, настройки, ошибки и уведомления используют один словарь. В SDK 0.6.49 нет локализации манифеста: исходные name/description английские; собственные подписи навигации и списка плагинов переводит доверенный content script.

## Что требует внимания

В счётчик, уведомления и пакетный запуск входят открытые issue/PR других людей и их новые комментарии/ревью. Боты вынесены во вкладку «Боты». Наши заявки в маркетплейс без замечаний и ошибок имеют спокойный статус «Ждёт маркетплейс» во вкладке «Все»; чужой комментарий/ревью или красная проверка PR требуют внимания. Причина ошибки проверки подписана явно.

Заявка маркетплейса группируется по Git-источнику изменённой записи `entries/<id>.json`. Агент запускается в разделе и checkout этого плагина, сохраняя исходную ссылку GitHub. Неоднозначная или нераспознанная запись даёт ошибку и блокирует запуск.

Выключенные на хабе и архивные репозитории исключены из слежения; дополнительно есть настройка «Не следить». Agency исключён по умолчанию. CI основной ветки опрашивается только для включённых установленных плагинов. Группы без пунктов внимания в этой вкладке скрыты; кнопка «Разобрать всё новое» создаёт максимум одного агента на плагин, объединяя обычные пункты и заявки маркетплейса.

Обычный запуск поручает агенту самостоятельно решить: принять, взять частично или вежливо отклонить с причиной; реализовать принятое, проверить, выпустить тег и GitHub Release, обновить хаб/маркетплейс при необходимости, поблагодарить @автора, ответить и закрыть пункт. Замечания к нашей заявке маркетплейса исправляются в её ветке с ответом сопровождающему; его решение о merge не подменяется. Пользовательские шаблоны сохраняются, прежний встроенный контракт обновляется автоматически. Опция «Только отчёт» остаётся отдельным ограниченным режимом.

## Работа

Откройте Repo Pulse → Settings. Укажите проект BB, машину, папку с checkout; нажмите Scan checkouts. Карта читается по `git remote origin` без изменения репозиториев; ручные значения имеют приоритет. Repo Pulse получает разделы через RPC `sections_list` плагина project-folders и сопоставляет точный путь checkout и машину. На карточках и в настройках показаны раздел и рабочая папка; ссылка «изменить» открывает родной select для выбора другого раздела. Кнопка «Создать раздел» регистрирует существующий checkout под выбранным родительским разделом через project-folders. Содержимое папки и её путь не перемещаются. Пустой список репозиториев обнаруживает `bb-plugin-*` и `claude-lane-stack` владельца VKirill. По умолчанию опрос раз в 15 минут. Кнопка Check now запускает его сразу.

Провайдер по умолчанию `codex`, модель `gpt-6.1-sol`, reasoning `high`, permission `full`; всё доступно в настройках. Контракт агента редактируется там же. Переменные: `{{checkoutPath}}`, `{{repo}}`, `{{itemUrl}}`, `{{itemKind}}`, `{{itemNumber}}`, `{{author}}`.

Токен читается на сервере из секретной настройки `githubToken`, затем из Env Catalog `GH_TOKEN`. В браузер не передаётся. Анонимный доступ допускает 60 запросов/час, плагин ограничивает себя 45, сохраняя бюджет между перезагрузками. HTTP-кеш поддерживает ETag/If-None-Match; тела обсуждений не сохраняются. Ошибки источников видны на экране; неполный ответ не закрывает пункт.

Run agent объединяет новые пункты репозитория в один тред. Запуск блокируется, если отсутствует раздел, рабочая папка не существует, не является Git-корнем или её origin отличается от выбранного репозитория. Проект и машина берутся из связки раздела, рабочий каталог — только из проверенного checkout. После spawn выполняется штатный `thread_place` с точным folderId; при ошибке размещения агент останавливается. Явный выбор другого раздела меняет место треда в дереве, сохраняя рабочую папку репозитория. Process all new запускает максимум один тред на репозиторий. Повторный запуск блокируется, пока связанный агент работает; жизненный цикл переводит карточки в Waiting for you. Закрытие на GitHub переводит в Done, обновление прочитанного пункта возвращает New; Muted остаётся заглушённым.

> [!IMPORTANT]
> Автоматический режим выключен. При включении новые пункты получают агента с явным ограничением: только исследование, отчёт и локальная ветка, без merge, push, релиза и публичных ответов до разрешения владельца. Это ограничение промпта; permission full остаётся правом процесса, поэтому для строгой изоляции используйте более ограниченные разрешения и отдельный checkout.

Массовое действие недоступно при включённом предпросмотре или режиме «Только отчёт». Режим «Только отчёт» запускает реального агента с отдельным промптом, который разрешает только чтение и отчёт, запрещает изменения файлов, ветки и публичные действия.

Preview launches проверяет кнопку Run agent и итоговый контракт без создания треда или старта писателя. В этом режиме массовый запуск недоступен. Repo Pulse сериализует собственные запуски; не предоставляет глобальную блокировку checkout для посторонних тредов или внешних CLI. Для репозиториев с другой активной работой сначала дождитесь её завершения.

### Счётчик и уведомления

Счётчик внимания находится в родном `headerContent` заголовка страницы и на экране. SDK содержит `experimental_sidebarAccessory`, но оболочка его не монтирует; ядро BB не меняется. Новые пункты вызывают нативный Sonner toast во всех открытых окнах BB; при закрытых клиентах пункты сохраняются до открытия. Отдельного публичного backend API для долговечных уведомлений SDK не предоставляет.

### CLI и инструменты

```sh
bb repo-pulse list --json
bb repo-pulse refresh
bb repo-pulse run '<item-id>' --dry-run
bb repo-pulse run '<item-id>'
```

`repo_pulse_list` — только чтение, максимум 50 пунктов, без вызовов модели. [Skill](skills/repo-pulse/SKILL.md).

## Разработка и доставка

```sh
npm ci
bb plugin types
npm run typecheck
npm test
bb plugin build
bb plugin update repo-pulse
gitnexus analyze
```

Установка на хаб:

```sh
bb plugin install 'git:https://github.com/VKirill/bb-plugin-repo-pulse.git@^0.1.0' --yes
```

Git-установка ставит production-зависимости и собирает backend/app/host на хабе. После проверки и push нового тега `vX.Y.Z` обновление получает общая автоматизация; вручную — `bb plugin update repo-pulse`. `.gitnexus/` и генерируемые локальные инструкции не публикуются.

Откат: `bb plugin disable repo-pulse`; восстановить предыдущую исправную установку/тег штатным менеджером плагинов. Секреты и KV не удалять. Uninstall удаляет настройки и состояние и для временной остановки не подходит.

## Ограничения и проверка

Опциональные security/Dependabot alerts отдельным источником не реализованы (обычные PR бота доступны во вкладке «Боты»). REST-списки ограничены 1000 записями на endpoint, выдача UI — 2000 карточек; marketplace search — 100 открытых PR. Недостающие страницы дают явную ошибку. CI показывает последний запуск основной ветки; успешный последний запуск закрывает предыдущие CI-карточки.

Проверка 0.1.5: 46 тестов, typecheck/build. Автотесты покрывают ETag, дедупликацию, повторное обновление прочитанного, карту origin, контракт, safe preview, пакетный запуск и события треда. Живые проверки и точная версия хаба фиксируются в отчёте текущего релиза. В маркетплейс плагин не отправлялся.
