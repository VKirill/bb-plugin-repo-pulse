# Repo Pulse — пульс собственных плагинов

Отслеживает входящие issue, PR, комментарии, ревью, ошибки CI и заявки владельца в маркетплейс. Показывает пункты по репозиториям и создаёт связанный тред агента. Интерфейс: English по умолчанию; русский при `document.documentElement.lang=ru*`, маркере языка Pokecut или активном русификаторе BB, оставляющем html lang английским. Заголовок, счётчик, статусы, кнопки, настройки, ошибки и уведомления используют один словарь. В SDK 0.6.49 нет локализации манифеста: исходные name/description английские; собственные подписи навигации и списка плагинов переводит доверенный content script.

## Что требует внимания

В счётчик, уведомления и пакетный запуск входят открытые issue/PR других людей и их новые комментарии/ревью. Боты вынесены во вкладку «Боты». Наши заявки в маркетплейс без замечаний и ошибок имеют спокойный статус «Ждёт маркетплейс» во вкладке «Все»; чужой комментарий/ревью или красная проверка PR требуют внимания. Причина ошибки проверки подписана явно. Если единственный провал — `gate:v1` с подтверждённым сообщением `Frozen v1 entries changed` и требованием метки `v1-change`, показывается «Ждёт метку сопровождающего» только во вкладке «Все». Проверяются шаги job и аннотации/лог; иной провал, смешанные ошибки и недоступное подтверждение остаются во внимании. Сырые логи не сохраняются, результат завершённой проверки кешируется по id/времени завершения.

Заявка маркетплейса группируется по Git-источнику изменённой записи `entries/<id>.json`. Агент запускается в разделе и checkout этого плагина, сохраняя исходную ссылку GitHub. Неоднозначная или нераспознанная запись даёт ошибку и блокирует запуск.

Активные собственные заявки маркетплейса обрабатываются одинаково, даже если соответствующий установленный плагин выключен: исправлять нашу заявку всё равно нужно. Явная настройка «Не следить» применяется и к ним. Выключенные на хабе и архивные репозитории исключены из обычного слежения; дополнительно есть настройка «Не следить». Agency исключён по умолчанию. CI основной ветки опрашивается только для включённых установленных плагинов. Группы без пунктов внимания в этой вкладке скрыты; кнопка «Разобрать всё новое» создаёт максимум одного агента на плагин, объединяя обычные пункты и заявки маркетплейса.

## Два этапа

«Запустить агента» и «Разобрать всё новое» начинают только **Анализ** — один тред на плагин, отдельная развёртка по каждому пункту. Агент читает запрос, обсуждение и весь diff PR, сверяет актуальный main, код, безопасность, EN/RU и Pokecut. По-русски объясняет просьбу и цель, реализацию и варианты, рекомендацию принять/частично/отклонить с причиной, риски, затронутые части, объём и план проверки; прикладывает английский черновик ответа автору. На этом этапе запрещены изменения файлов/Git и любые публичные действия.

После анализа карточка показывает **«Ждёт вашего решения»** и кнопки **«Внедрить» / «Отклонить»**. Они продолжают тот же тред через SDK, создавая разрешение только для выбранного пункта. Можно ответить владельцем в самом треде: «внедряй», «не надо», «вариант 2». Уточнение или сообщение другого агента не считается решением.

После разрешения агент реализует выбранное, тестирует, выпускает тег и GitHub Release, доставляет обновление на хаб прежним способом, обновляет маркетплейс при необходимости, отвечает с благодарностью @автору и закрывает пункт. При отказе — вежливый ответ с причиной и закрытие без реализации. Наша заявка маркетплейса исправляется в своей ветке с ответом сопровождающему; его merge не подменяется.

Статусы: **Новое → Анализ → Ждёт вашего решения → Внедряется → Готово / Отклонено**. Если реализация остановилась на блокере, карточка снова ждёт решения. Автоматический режим тоже делает только анализ. Дублирующий переключатель «Только отчёт» удалён. Пользовательские шаблоны сохраняются; предыдущие встроенные шаблоны мигрируют на двухэтапный контракт, а обязательное ограничение этапа анализа действует и для custom prompt.

## Работа

Откройте Repo Pulse → Settings. Укажите проект BB, машину, папку с checkout; нажмите Scan checkouts. Карта читается по `git remote origin` без изменения репозиториев; ручные значения имеют приоритет. Repo Pulse получает разделы через RPC `sections_list` плагина project-folders и сопоставляет точный путь checkout и машину. На карточках и в настройках показаны раздел и рабочая папка; ссылка «изменить» открывает родной select для выбора другого раздела. Кнопка «Создать раздел» регистрирует существующий checkout под выбранным родительским разделом через project-folders. Содержимое папки и её путь не перемещаются. Пустой список репозиториев обнаруживает `bb-plugin-*` и `claude-lane-stack` владельца VKirill. По умолчанию опрос раз в 15 минут. Кнопка Check now запускает его сразу.

Провайдер по умолчанию `codex`, модель `gpt-6.1-sol`, reasoning `high`, permission `full`; всё доступно в настройках. Контракт агента редактируется там же. Переменные: `{{checkoutPath}}`, `{{repo}}`, `{{itemUrl}}`, `{{itemKind}}`, `{{itemNumber}}`, `{{author}}`.

Токен читается на сервере из секретной настройки `githubToken`, затем из Env Catalog `GH_TOKEN`. В браузер не передаётся. Анонимный доступ допускает 60 запросов/час, плагин ограничивает себя 45, сохраняя бюджет между перезагрузками. HTTP-кеш поддерживает ETag/If-None-Match; тела обсуждений не сохраняются. Ошибки источников видны на экране; неполный ответ не закрывает пункт.

Запуск объединяет новые пункты плагина в один тред. Отсутствующий раздел, неправильный Git-корень/origin и чужой активный связанный тред блокируют его. Проект и host берутся из раздела, рабочий каталог — из проверенного checkout; после spawn выполняется штатный `thread_place`, при ошибке размещения агент останавливается. Выбор другого раздела сохраняет рабочую папку репозитория. Новый анализ не создаёт второй тред, пока предыдущий ждёт решения владельца.

Предпросмотр проверяет связку и итоговый промпт без треда; массовая кнопка в нём недоступна. Repo Pulse сериализует собственные запуски и решения, но не блокирует посторонние CLI/треды. Прежде чем разрешать внедрение, завершите несвязанную работу в том же checkout.

> [!IMPORTANT]
> Автоматический режим выключен по умолчанию. При включении он только анализирует. Разрешения процесса остаются настройкой провайдера; запрет действий первого этапа задаётся обязательным контрактом и проверяется живым сценарием.

### Счётчик и уведомления

Счётчик внимания находится в родном `headerContent` заголовка страницы и на экране. SDK содержит `experimental_sidebarAccessory`, но оболочка его не монтирует; ядро BB не меняется. Новые пункты вызывают нативный Sonner toast во всех открытых окнах BB; при закрытых клиентах пункты сохраняются до открытия. Отдельного публичного backend API для долговечных уведомлений SDK не предоставляет.

### CLI и инструменты

```sh
bb repo-pulse list --json
bb repo-pulse refresh
bb repo-pulse run '<item-id>' --dry-run
bb repo-pulse run '<item-id>'
bb repo-pulse decide '<item-id>' implement 'выбранный вариант'
bb repo-pulse decide '<item-id>' reject 'причина владельца'
bb repo-pulse track VKirill/bb-plugin-repo-pulse 1
```

Обычные собственные issue не создают шум. `track` явно импортирует указанный issue/PR владельца (в том числе тестовый) и отслеживает его закрытие.

`repo_pulse_list` — только чтение, максимум 50 пунктов, без вызовов модели. [Skill](skills/repo-pulse/SKILL.md).

## Разработка и доставка

```sh
npm ci
bb plugin types
npm run typecheck
npm test
bb plugin build
bb plugin update repo-pulse
gitnexus analyze
```

Установка на хаб:

```sh
bb plugin install 'git:https://github.com/VKirill/bb-plugin-repo-pulse.git@^0.1.0' --yes
```

Git-установка ставит production-зависимости и собирает backend/app/host на хабе. После проверки и push нового тега `vX.Y.Z` обновление получает общая автоматизация; вручную — `bb plugin update repo-pulse`. `.gitnexus/` и генерируемые локальные инструкции не публикуются.

Откат: `bb plugin disable repo-pulse`; восстановить предыдущую исправную установку/тег штатным менеджером плагинов. Секреты и KV не удалять. Uninstall удаляет настройки и состояние и для временной остановки не подходит.

## Ограничения и проверка

Опциональные security/Dependabot alerts отдельным источником не реализованы (обычные PR бота доступны во вкладке «Боты»). REST-списки ограничены 1000 записями на endpoint, выдача UI — 2000 карточек; marketplace search — 100 открытых PR. Недостающие страницы дают явную ошибку. CI показывает последний запуск основной ветки; успешный последний запуск закрывает предыдущие CI-карточки.

Проверка 0.1.7: 72 теста, typecheck/build. Автотесты покрывают ETag, дедупликацию, повторное обновление прочитанного, карту origin, контракт, safe preview, пакетный запуск и события треда. Живые проверки и точная версия хаба фиксируются в отчёте текущего релиза. В маркетплейс плагин не отправлялся.
