# Repo Pulse — пульс собственных плагинов

Отслеживает входящие issue, PR, комментарии, ревью, ошибки CI и заявки владельца в маркетплейс. Показывает пункты по репозиториям и создаёт связанный тред агента. Интерфейс: English по умолчанию, русский при `document.documentElement.lang=ru`.

## Работа

Откройте Repo Pulse → Settings. Укажите проект BB, машину, папку с checkout; нажмите Scan checkouts. Карта читается по `git remote origin` без изменения репозиториев; ручные значения имеют приоритет. Пустой список репозиториев обнаруживает `bb-plugin-*` и `claude-lane-stack` владельца VKirill. По умолчанию опрос раз в 15 минут. Кнопка Check now запускает его сразу.

Провайдер по умолчанию `codex`, модель `gpt-6.1-sol`, reasoning `high`, permission `full`; всё доступно в настройках. Контракт агента редактируется там же. Переменные: `{{checkoutPath}}`, `{{repo}}`, `{{itemUrl}}`, `{{itemKind}}`, `{{itemNumber}}`, `{{author}}`.

Токен читается на сервере из секретной настройки `githubToken`, затем из Env Catalog `GH_TOKEN`. В браузер не передаётся. Анонимный доступ допускает 60 запросов/час, плагин ограничивает себя 45, сохраняя бюджет между перезагрузками. HTTP-кеш поддерживает ETag/If-None-Match; тела обсуждений не сохраняются. Ошибки источников видны на экране; неполный ответ не закрывает пункт.

Run agent объединяет новые пункты репозитория в один тред. Process all new запускает максимум один тред на репозиторий. Повторный запуск блокируется, пока связанный агент работает; жизненный цикл переводит карточки в Waiting for you. Закрытие на GitHub переводит в Done, обновление прочитанного пункта возвращает New; Muted остаётся заглушённым.

> [!IMPORTANT]
> Автоматический режим выключен. При включении новые пункты получают агента с явным ограничением: только исследование, отчёт и локальная ветка, без merge, push, релиза и публичных ответов до разрешения владельца. Это ограничение промпта; permission full остаётся правом процесса, поэтому для строгой изоляции используйте более ограниченные разрешения и отдельный checkout.

Preview launches проверяет кнопку Run agent и итоговый контракт без создания треда или старта писателя. В этом режиме массовый запуск недоступен. Repo Pulse сериализует собственные запуски; не предоставляет глобальную блокировку checkout для посторонних тредов или внешних CLI. Для репозиториев с другой активной работой сначала дождитесь её завершения.

### Счётчик и уведомления

Счётчик внимания находится в родном `headerContent` заголовка страницы и на экране. SDK содержит `experimental_sidebarAccessory`, но оболочка его не монтирует; ядро BB не меняется. Новые пункты вызывают нативный Sonner toast во всех открытых окнах BB; при закрытых клиентах пункты сохраняются до открытия. Отдельного публичного backend API для долговечных уведомлений SDK не предоставляет.

### CLI и инструменты

```sh
bb repo-pulse list --json
bb repo-pulse refresh
bb repo-pulse run '<item-id>' --dry-run
bb repo-pulse run '<item-id>'
```

`repo_pulse_list` — только чтение, максимум 50 пунктов, без вызовов модели. [Skill](skills/repo-pulse/SKILL.md).

## Разработка и доставка

```sh
npm ci
bb plugin types
npm run typecheck
npm test
bb plugin build
bb-plugin-push repo-pulse
gitnexus analyze
```

Первичная установка: собрать на Mac mini, rsync исходников и `dist/` в зеркальный путь хаба (без `.git`, `node_modules`, `.gitnexus`), на хабе `npm install --omit=dev --ignore-scripts`, затем `bb plugin install path:<hub-path> --yes`. Серверный и host bundle самодостаточны; UI собран в app bundle, runtime-shims предоставляет BB.

Откат: `bb plugin disable repo-pulse`; восстановить предыдущий тег в отдельном checkout, собрать, доставить и `bb plugin enable repo-pulse`. KV-данные при disable/reload сохраняются. Uninstall удаляет настройки и состояние.

## Ограничения и проверка

Опциональные security/Dependabot alerts отдельным источником не реализованы (обычные PR бота попадают в общий поток). REST-списки ограничены 1000 записями на endpoint, выдача UI — 2000 карточек; marketplace search — 100 открытых PR. Недостающие страницы дают явную ошибку. CI показывает последний запуск основной ветки; успешный последний запуск закрывает предыдущие CI-карточки.

Автотесты покрывают ETag, дедупликацию, повторное обновление прочитанного, карту origin, контракт, safe preview, пакетный запуск и события треда. Живые проверки и точная версия хаба фиксируются в отчёте текущего релиза. В маркетплейс плагин не отправлялся.
